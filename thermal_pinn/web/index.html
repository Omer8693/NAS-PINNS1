1. Introduction

Thermal quenching is a critical manufacturing process in the production of aluminium castings, wherein a hot workpiece — typically at temperatures near 500 °C — is rapidly immersed in a cooling medium such as water. The resulting transient heat transfer process governs the development of residual stresses, microstructural changes, and the final mechanical properties of the component [8]. Accurate simulation of this process is therefore essential for industrial quality control, yet it remains computationally demanding when performed using traditional numerical methods.

Finite Element Methods (FEM) represent the current state of the art for such simulations. They discretise the governing transient heat equation — including convective boundary conditions with high heat transfer coefficients (h ≈ 5000 W/m²K) — into a sequence of linear systems solved at each timestep ΔtFEM = 1.5 s. While FEM solutions are highly accurate, the computational cost scales poorly with mesh refinement and the number of timesteps required to resolve the full 30-second quenching transient. For complex three-dimensional geometries such as cylinders, L-shaped sections, and stacked components, this cost becomes prohibitive in iterative design workflows.

Physics-Informed Neural Networks (PINNs) [1] have emerged as a mesh-free alternative to conventional numerical solvers. By embedding the governing PDEs directly into the neural network loss function, PINNs can approximate solutions without requiring spatial discretisation. However, vanilla PINNs suffer from spectral bias [2] — the tendency to learn low-frequency components while struggling with high-frequency spatial gradients — and sensitivity to loss weight balancing. Moreover, solution quality is highly sensitive to the choice of network architecture, which has historically required extensive manual tuning.

Neural Architecture Search (NAS) addresses this limitation by automating the search for optimal network configurations. Wang & Zhong [7] demonstrated that NAS-guided PINNs can discover architectures that significantly outperform hand-designed networks on benchmark PDE problems. This work applies three NAS strategies — Bayesian optimisation via Tree-structured Parzen Estimators (TPE) [4], NSGA-II [5], and NSGA-III [6] — to systematically find the best PINN architecture for each quenching domain and geometry.

A key contribution is the k-Skip Multi-Step Window Prediction (MSWP) strategy. Rather than training a single PINN over the full 30-second transient, the time domain is decomposed into short windows. Within each window, the PINN predicts k consecutive FEM timesteps simultaneously (k ∈ {1…5}), where k represents a trade-off between the number of windows and the difficulty of each local prediction. The network output exactly satisfies the initial condition at each window boundary by construction:

T̂(x, τ) = Tic(x) + τ · Nθ(x, τ, Tic)

where τ ∈ [0,1] is normalised time within the window and Tic(x) is the FEM temperature field at the window start. Training progressed through three successive stages: (1) cold-start — 800 Adam epochs per window from random initialisation; (2) v2 — Fourier feature embedding [2] and self-adaptive loss weights [3] to overcome spectral bias; (3) warm-start — fine-tuning each window from the previous window's weights (500 epochs), reducing total training time by 38% with no significant accuracy loss.

2. Step 1 — Cold-Start Baseline (800 Epochs)

The cold-start experiment trains each (domain, architecture, k) combination independently for 800 Adam epochs (lr = 10⁻³) followed by 50 L-BFGS iterations. The NAS search space spans layer depth (2–6), width (32–256 neurons), and activation function (ReLU, Tanh, GELU) over 60 trials per optimizer. Steady-state metrics exclude the first three windows (transient phase, t < 4.5 s).

All three 2D domains achieved relative L2 < 5%, confirming that the k-Skip MSWP approach is viable for planar geometries. 3. Step 2 — Architectural Improvements: Fourier + Self-Adaptive (v2)

Analysis of cold-start error patterns revealed degraded prediction quality in regions with steep thermal gradients, consistent with spectral bias [2]. The v2 architecture introduces Fourier feature embedding to map input coordinates to a high-dimensional feature space, allowing the MLP to capture high-frequency temperature variations:

γ(v) = [sin(2π Bv), cos(2π Bv)], B ∈ ℝd×F, F=64, σ=1.0 (2D) / 1.5 (3D)

Self-adaptive loss weights [3] replace fixed λ values with learnable parameters optimised jointly with the network (dual learning rate: ηmodel = 10⁻³, ηλ = 10⁻⁴). For NSGA-II and NSGA-III, training was extended to 1500 epochs plus 150 L-BFGS iterations. 4. Step 3 — Warm-Start Fine-Tuning (500 Epochs)

The cold-start approach retrains each window from random initialisation, discarding structural similarity between consecutive windows. Warm-start initialises each window's training from the previous window's converged weights. Window 1 is trained cold (800 ep); all subsequent windows fine-tune for 500 epochs at lr = 10⁻³. This yields a 38% reduction in total training time across a 20-window simulation (k=1) with comparable accuracy.

The MAE comparison plots below show all three strategies per domain: cold (dashed), v2 (dotted), and warm-start (solid). For 2D domains, warm-start tracks cold-start closely. For 3D domains with complex geometry, warm-start occasionally increases error when the window-to-window temperature evolution is large — the recommendation matrix identifies these cases explicitly.

6. Summary and Recommendations

This study presents a three-stage framework for accelerating transient thermal quenching simulations using NAS-optimised PINNs. The k-Skip MSWP strategy reduces sequential PINN training runs from 20 windows (k=1) to as few as 4 (k=5), with optimal k varying by geometry and architecture. The progression from cold-start to v2 (Fourier + self-adaptive) to warm-start fine-tuning reveals a consistent improvement in the accuracy–efficiency trade-off at each stage. For 2D domains, all tested configurations satisfy Rel. L2 < 5%. For 3D, 7 of 12 configurations (domain × architecture) meet this target.

The recommended deployment pipeline: (1) run NAS (60 trials) to find the optimal architecture; (2) apply v2 training (Fourier + self-adaptive) for improved accuracy; (3) use warm-start fine-tuning for production runs to reduce per-simulation training time by 38%.
